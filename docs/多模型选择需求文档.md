文档二：开发文档
v1.1 多模型选择 — 实施方案 归档路径建议：docs/v1.1-multi-model-dev.md

1. 关键设计决策
D1｜catalog 分层。 能力元数据（supports_tools 等）写代码常量，因其决定代码走哪条分支，必须被测试覆盖；key 与启用开关写 .env，因其与密钥同源、换机器即变。此分层与 Codex 接入 DeepSeek 的做法一致 —— Codex 用 config.toml 管 provider 与 key，用 ~/.codex/models.json 声明模型能力元数据。

D2｜client 按 provider 缓存，不按 model。 同 provider 的多个 model_id 只是请求参数不同，共用一个 OpenAI() 实例即可，能复用底层 HTTP 连接池。

D3｜SummaryService 固定用默认模型，不跟随用户选择。 两个理由：摘要是用户不可见的后台任务，用贵模型无收益；更重要的是摘要结果会注入后续所有请求的上下文，若跟随用户选择，同一会话的摘要质量会随机波动，问题不可复现。

D4｜第一版全部走 chat_completions。 wire_api 字段先占位，值恒为 chat_completions。DeepSeek 与 OpenAI 均支持，现有代码零改动。

D5｜thinking 在同一 ReAct 循环内必须回传，跨用户轮次剥离。 DeepSeek 在模型产生工具调用后要求后续请求回传 reasoning_content；因此它必须保留到本次请求的工具循环结束。同时 thinking 不落 SQLite、不进入下一条用户消息的历史上下文，仅作为 SSE 事件透传给前端。

def available_models() -> dict[str, ModelSpec]:
    enabled = {s.strip() for s in os.getenv("ENABLED_MODELS", "").split(",") if s.strip()}
    providers = load_provider_configs()          # 只含 key 已配置的 provider
    result = {
        mid: spec for mid, spec in MODEL_CATALOG.items()
        if mid in enabled and spec.provider in providers
    }
    if not result:
        raise RuntimeError(
            f"没有可用模型。ENABLED_MODELS={enabled or '（空）'}，"
            f"已配置 key 的 provider={set(providers) or '（无）'}"
        )
    return result
3.2 client 池（FR-4.2 线程安全）

import threading
from openai import OpenAI

_clients: dict[str, OpenAI] = {}
_lock = threading.Lock()

def get_client(provider: str) -> OpenAI:
    client = _clients.get(provider)          # 快路径：无锁读
    if client is not None:
        return client
    with _lock:
        if provider not in _clients:         # 双重检查
            cfg = load_provider_configs()[provider]
            _clients[provider] = OpenAI(api_key=cfg.api_key, base_url=cfg.base_url)
        return _clients[provider]
3.3 单次流式调用（FR-7，最高风险模块）

def _stream_round(self, messages, spec, tool_choice="auto"):
    """一轮模型调用。同时产出 token / thinking 事件并累积 tool_calls。"""
    kwargs = {
        "model": spec.api_model,
        "messages": messages,
        "stream": True,
        "stream_options": {"include_usage": True},
        **spec.top_level_params,
    }
    if spec.extra_body:
        kwargs["extra_body"] = spec.extra_body
    tools = self._active_tools()
    if spec.supports_tools and tools:
        kwargs["tools"] = tools
        kwargs["tool_choice"] = tool_choice

    acc: dict[int, dict] = {}          # index -> {id, name, arguments}
    content_parts, reasoning_parts = [], []
    usage = finish_reason = None

    timings.bump("llm_calls")
    started = time.perf_counter()
    with timings.track("llm"):
        for chunk in get_client(spec.provider).chat.completions.create(**kwargs):
            if getattr(chunk, "usage", None):
                usage = chunk.usage
            if not chunk.choices:
                continue
            choice = chunk.choices[0]
            if choice.finish_reason:
                finish_reason = choice.finish_reason
            delta = choice.delta

            reasoning = getattr(delta, "reasoning_content", None)
            if reasoning:
                reasoning_parts.append(reasoning)
                yield StreamEvent(type="thinking", data={"text": reasoning})

            if delta.content:
                content_parts.append(delta.content)
                yield StreamEvent(type="token", data={"text": delta.content})

            for tc in (delta.tool_calls or []):
                slot = acc.setdefault(tc.index, {"id": "", "name": "", "arguments": ""})
                if tc.id:
                    slot["id"] = tc.id
                if tc.function:
                    if tc.function.name:
                        slot["name"] = tc.function.name
                    if tc.function.arguments:
                        slot["arguments"] += tc.function.arguments   # 字符串拼接，不是 dict merge

    self._record_llm_call(
        model_id=spec.model_id,
        usage=usage,
        finish_reason=finish_reason,
        cost_ms=int((time.perf_counter() - started) * 1000),
    )
    return _RoundResult(
        content="".join(content_parts),
        tool_calls=[acc[i] for i in sorted(acc)],
        reasoning="".join(reasoning_parts),
    )
三个必须注意的点：

arguments 是字符串分片，必须 += 拼接，全部收完才能 json.loads。中途解析必然抛 JSONDecodeError
tc.index 是分组键，不是列表下标。并行多工具调用时 index 会交错到达
usage 通常在最后一个 chunk，且该 chunk 的 choices 为空 —— 所以 if not chunk.choices: continue 必须放在读 usage 之后
当本轮产生 tool_calls 时，_RoundResult.reasoning 必须写入 assistant 消息的 reasoning_content 字段，再追加 tool 结果。该字段只在本次 run_stream 的 working_messages 中存活，不写入 conversations，不进入下一条用户消息。
3.4 版本化 parser（FR-9.4）

def parse_stored_reply(reply_raw: str, reply_format: str) -> TutorReply:
    if reply_format == "markdown_v2":
        return TutorReply(answer=reply_raw, sources=[])
    if reply_format == "json_v1":
        data = json.loads(reply_raw)                 # 旧数据保证是 JSON
        return TutorReply(answer=data.get("answer", ""), sources=[])
    raise ValueError(f"未知的 reply_format: {reply_format}")
