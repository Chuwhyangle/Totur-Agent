# Totur-Agent v1.0 开发计划书

> 版本:v1.0 草案 · 基线代码:commit `d9925a7` · 目标:当天上线远程可用

## 1. 背景与目标

**愿景**:把 Totur-Agent 从"面试准备项目"升级为**每天深度使用的个人 AI 学习工作台**(替代 DEEIX),部署在自有服务器上,任意设备 web 远程访问。

**双重价值**:
- 日用:每日学习问答、笔记检索、信息记录的唯一入口
- 简历:补上"生产化部署 + 运维"的真实经验(容器化、反代、数据迁移、备份恢复)

**本期目标(v1.0)**:
1. 基础框架与功能收尾(配置化重构 + must-have 功能验证)
2. 服务器上线:远程 web 正常使用,数据持久不丢

**非目标(明确不做,防范围失控)**:
- ❌ 多用户/注册系统(单人自用,v2 再上应用层 JWT)
- ❌ 无鉴权裸奔公网(v1 公网部署,但 nginx Basic Auth + HTTPS 限定仅本人访问)
- ❌ k8s / 多机高可用(单机 docker-compose 足够)
- ❌ 检索/Agent 架构重写(现有链路已达标,只做配置化改造)

## 3. 目标架构(v1.0)

```text
你的电脑 / 手机(任意浏览器)
        │  HTTPS :443(Basic Auth,仅你知道凭据)
        ▼
┌─ 服务器(VPS · Ubuntu 22.04 · 2C4G)────────────────┐
│  nginx :443(TLS + Basic Auth;:80 仅 301 跳转)     │
│   ├─ /        → 前端静态文件(vite build 产物)      │
│   └─ /api/*   → 反代 backend:8001                    │
│                                                       │
│  backend 容器(uvicorn + FastAPI)                    │
│   ├─ /data/tutor_agent.db    (volume)                │
│   ├─ /data/chroma_db         (volume)                │
│   └─ /data/uploads           (volume,临时 PDF)      │
│                                                       │
│  外呼依赖:LLM API / Embedding API / Reranker API    │
└───────────────────────────────────────────────────────┘
```

**三个关键决策**:
1. **同域部署**:前端静态与 `/api` 同域 → CORS 从根上消失(TD-2 顺带解决)
2. **公网 + nginx Basic Auth + HTTPS**:v1 用最小代价限定"仅本人访问"——htpasswd 强随机密码,鉴权在 nginx 层覆盖包括 `/api` 在内的所有路径(TD-5 缓解);应用层 JWT 登录留给 v2
   - 有域名 → Let's Encrypt(certbot)签发证书
   - 无域名 → 自签名证书(浏览器警告可接受);**不要**长期跑纯 HTTP,Basic Auth 凭据和对话内容会明文传输
3. **状态集中 `/data`**:一个挂载点管所有持久化(TD-3/4 的解法,TD-7 备份的基础)

### 6.1 D4 "每日记录"设计(三步演进)

**设计目标**:把记录摩擦降到"跟 agent 说一句话就算记完了"——日用软件能否坚持,取决于记录成本。

| 步骤 | 内容 | 成本 | 得到什么 |
|---|---|---|---|
| **A** | 新增"日记"persona + 固定日记 session,写入=聊天 | 0(配置级) | 今天就能用;缺点:无日期结构、不可检索 |
| **B** | `journal_entries(id, entry_date, content, tags, mood, created_at)` 表 + `/journal` CRUD API + 前端日历/列表页 | ~半天 | 结构化存储,按日期精确回看("上周二记了什么") |
| **C** | ① Agent 工具 `save_journal_entry`:任意会话里说"记一下:今天搞定了部署",ReAct 循环自动调工具落库;② journal 作为一个逻辑分片:entry 写入时 chunk + embed 进 `learning_notes_journal` collection | ~2h(B 之上) | **对话即记录**;shard_router 广播检索自动覆盖日记,MCP 动态分片工具注册自动暴露 `search_journal_notes`——agent"记得你做过什么" |

**为什么这么设计**:C 步几乎零新架构——完全复用已有的工具注册表、分片路由、MCP 动态工具注册三件套;且"对话即记录 + 记录可语义检索"正是替代 DEEIX 的差异化能力。
**检索双路径**:时间维度查询(上周做了什么)走 B 的 SQL 按日期查;语义回忆(我之前怎么解决 CORS 的)走 C 的分片检索。两者互补,不要用向量检索硬扛时间类查询。

## 10. 风险与对策

| 风险 | 概率 | 对策 |
|---|---|---|
| 服务器访问 LLM API 不通(地域/网络) | 中 | M1 第一步先验证;不通换地域或换 base_url 中转 |
| chromadb 拷贝后索引不可读 | 低 | 版本已锁 1.5.9;兜底用 corpus 重建索引 |
| PyMuPDF/chromadb 容器构建失败(系统依赖) | 中 | slim 镜像补 build-essential,或直接换全量镜像 |
| SQLite 并发写锁 | 低 | 单人自用 + WAL 模式,足够 |
| 前端 build 后路由/资源路径 404 | 中 | nginx SPA fallback(`try_files ... /index.html`) |
| Basic Auth 密码被暴力破解 | 低 | 强随机密码(20+ 位);可选 fail2ban 封禁高频 401 IP |
| 无 HTTPS 时凭据/对话明文传输 | 中 | 有域名上 certbot;无域名用自签名证书,不长期跑纯 HTTP |
| 今天时间不够 | 中 | **砍 Phase D,保 R1-R4 + M1-M4**;功能全部延后,上线不延 |
