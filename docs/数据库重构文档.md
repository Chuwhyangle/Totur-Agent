A1 — 引入 Engine 与连接池
现状：DATABASE_PATH 是模块导入时求值的常量，46 处 get_connection() 每次新建 sqlite3.connect()。

怎么做

新建 app/db/engine.py：


from sqlalchemy import create_engine

_engine = None

def get_engine():
    global _engine
    if _engine is None:
        url = settings.database_url          # sqlite:///... 或 mysql+pymysql://...
        kwargs = dict(pool_pre_ping=True, future=True)
        if url.startswith("mysql"):
            kwargs.update(
                pool_size=5,
                max_overflow=10,
                pool_recycle=3600,           # 必须 < MySQL wait_timeout(默认 28800)
                pool_timeout=10,
                connect_args={"init_command": "SET time_zone = '+00:00'"},
            )
        _engine = create_engine(url, **kwargs)
    return _engine

def reset_engine_for_tests():
    global _engine
    if _engine is not None:
        _engine.dispose()
    _engine = None

A3 — 消除嵌套连接与双事务
现状：save_conversation() 在自身连接未关闭时调用 get_or_create_default_session() 和 touch_session()，两者各自再开连接。同时 INSERT 与 touch_session 是两个独立事务。

怎么做

被调方接受 Connection 参数，不得自开连接：

def touch_session(conn: Connection, session_id: int) -> None: ...
def get_or_create_default_session(conn: Connection, user_id: str, ...) -> ChatSessionRecord: ...

def save_conversation(...):
    with get_engine().begin() as conn:        # 单事务
        sid = session_id or get_or_create_default_session(conn, user_id).id
        result = conn.execute(text(INSERT_SQL), {...})
        touch_session(conn, sid)
        return result.lastrowid
全仓库排查同类模式：任何 repository 函数在持有连接期间调用另一个 repository 函数
嵌套连接在连接池下会自死锁（每请求持 1 条、申请第 2 条，pool_size 耗尽后全体阻塞），且低并发测不出来
验收标准

任一 repository 函数的调用栈中同时活跃的 Connection 不超过 1 个
save_conversation 的插入与 touch_session 在同一事务内，中途异常时两者一起回滚

C2 — 五层验收脚本
核心规则

验证器不得复用 ETL 的转换函数。否则同一个 bug 会同时骗过写入路径与校验路径。做法是反向转换，与未经改动的 SQLite 源数据比对：

mysql_dt = row["created_at"]                                  # naive datetime

4. 时间戳规范（唯一不可逆决策，单独强调）

存储层    UTC，DATETIME(6)
服务端    --default-time-zone=+00:00   --log-timestamps=UTC
应用连接  SET time_zone = '+00:00'          ← 必须是 +00:00，不是 +08:00
ETL       parse → astimezone(utc) → replace(tzinfo=None)
展示层    astimezone(ZoneInfo("Asia/Shanghai"))
人工查询  DBeaver/CLI 会话可自行 SET time_zone='+08:00'，不影响存储
现状 13 处生成点全部 datetime.now(timezone.utc).isoformat()，零 naive datetime，代码不需改动
精度必须 (6)：.isoformat() 产出 6 位微秒，MySQL 对超出 fsp 的小数位四舍五入且不报错，严格模式也不报。(6) vs (3) 只差 1 字节
应用连接用 +00:00 而非 +08:00：trace 表用 DEFAULT CURRENT_TIMESTAMP（服务端时钟），两者必须一致，否则跨库 JOIN 时间对不上
不用 TIMESTAMP 类型：自动时区转换 + 2038 溢出
journal_entries.entry_date 用本地日历日，与 created_at 语义不同，这是正确设计，靠 DATE 类型 + COMMENT 声明，不要"修复"
