## 3. 设计决策

1. **SSE 路由按线级协议验证**：通过 `TestClient` 请求真实 `/chat/stream` 路由，只 monkeypatch service generator，解析 `event:`/`data:`，验证顺序、JSON 格式、结构化 done、异常转换和提前结束。
2. **SQLite 完全隔离**：repository/API 测试把 `app.db.database.DATABASE_PATH` monkeypatch 到 pytest `tmp_path`，不写项目根 `tutor_agent.db`。
3. **备份完全隔离**：所有源目录、输出目录和归档解压目录均位于 `tmp_path`；SQLite 使用真实 `sqlite3 backup` 路径验证可读性与 `integrity_check`。
4. **前端分层测试**：API 层使用 mock ReadableStream reader 验证请求与 SSE 分派；App 层 mock `postChatStream` 验证文本累积、done/error 后发送状态清理及关闭流式时回退普通 chat。
5. **范围外生产缺口用严格 xfail 固化**：要求生产修改但文件不在允许范围内的缺口使用 `pytest.mark.xfail(strict=True)`，既记录预期失败，又能在将来实现修复后以 XPASS 使测试失败，提示移除 xfail。

## 8. 已知风险与未解决问题

1. **备份不完整**：`scripts/backup.py` 当前仅收集 SQLite 与 Chroma，未打包 corpus 和附件目录。

项目负责人在原工作包测试交付后，继续明确要求完成 SSE，使其可用于正式交互场景，并要求最终提交、推送。因此本阶段在既有失败回归测试基础上，对 SSE 生产链路做最小实现与资源清理；日记、备份、RAG、persona、数据库配置等其他工作区改动仍不纳入本次提交。

### 生产代码改动及理由

- `app/api/routes/chat.py`：提供 `/chat/stream`，统一输出 `token/tool_call/tool_result/done/error`；生成器无终态或提前结束时补 `error`；终态后停止继续读取；设置 `no-cache` 与 `X-Accel-Buffering: no`。
- `app/services/agent/react_orchestrator.py`：增加流式 ReAct 事件；最终 token 的拼接值作为生成器返回值，保证客户端文本、`done` 回复和持久化内容一致；关闭/取消时关闭模型 provider stream，且清理异常不覆盖原始异常。
- `app/services/tutor_agent_service.py`：连接 session、上下文、附件、ReAct 流和回复解析；转发工具事件，持久化最终一致回复并输出结构化 `done`，业务异常转换为 `error`。
- `frontend/src/api/tutorApi.js`：实现跨 chunk、CRLF 兼容的 SSE 解析；校验 HTTP 响应；`done/error` 为终态；无终态 EOF 明确失败；支持 `AbortSignal`。
- `frontend/src/App.jsx`：累积 token 与工具状态；`done/error/AbortError` 清理发送态；持有当前 `AbortController`，旧请求不能清除新请求状态；取消后不把临时内容固化为成功回复。
- `frontend/src/components/ChatInput.jsx`：流式开关和“停止生成”入口；非流式模式仍走普通 `/chat`。

### 新增或修改的回归测试

- `tests/test_chat_stream.py`：空流和提前结束转换为格式正确的 `error` 终态。
- `tests/test_agent_react_loop.py`：流式 token 与生成器最终返回值一致；取消生成器会关闭上游模型流。
- `frontend/src/api/tutorApi.test.js`：请求 URL/method/headers/body、跨块与 CRLF、事件累积、终态、错误、无终态 EOF、AbortError。
- `frontend/src/App.test.jsx`：token 展示、工具事件、done/error 状态清理、普通 chat 回退、停止生成与 signal 取消。

### TDD 与失败尝试

1. 回归测试先暴露空流/提前结束无终态，随后路由补充统一 `error` 事件。
2. 一致性测试先发现预检回复可能与真正流式 token 不同，随后以流式 token 拼接值作为最终回复。
3. 取消测试先暴露 provider stream 未关闭，随后在 `finally` 中做幂等清理，并避免 close 异常覆盖原始错误。
4. Windows 环境中的 `apply_patch` 返回 `Access is denied`，分类为编辑工具环境问题；改用等价最小 `git apply` 补丁，并在每次应用后检查目标 diff。
