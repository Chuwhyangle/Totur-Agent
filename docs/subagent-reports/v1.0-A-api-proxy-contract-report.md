# Totur-Agent v1.0 工作包 A：API/反向代理契约修正报告

## 1. 目标

固定生产 API 的单一前缀责任：前端请求 `/api/*`，反向代理去掉 `/api` 后转发到 FastAPI；FastAPI 保持无 `/api` 的真实路由。同步验证 `ROOT_PATH`、CORS 环境变量解析以及 `DATA_DIR` 对 SQLite/Chroma 路径的兼容性，并为 journal API 增加不依赖外部模型或网络的最小回归测试。

## 2. 范围与边界

允许范围仅为：

- `app/config.py`
- `app/main.py`
- `app/api/routes/journal.py`
- `tests/test_server_config.py`
- `tests/test_journal_api.py`
- 本报告

开始工作时工作区已有大量未提交改动，包括 `app/config.py`、`app/main.py` 以及其他业务、前端和运行产物文件。本工作包没有回退、覆盖或清理这些改动；没有修改 `frontend/`、Docker/Compose/nginx、Agent 核心、RAG、repository 或其他代理报告。

## 3. 设计决策

1. **单一前缀责任**：FastAPI 路由不声明 `/api`；nginx 负责对外 `/api` 与转发前去前缀。journal router 使用 `/journal`，最终真实路径为 `/journal/entries` 和 `/journal/entries/{entry_id}`。
2. **`ROOT_PATH` 只作代理上下文**：由 `FastAPI(root_path=...)` 使用，服务 OpenAPI/URL 生成；不拼接到 router prefix，因此不会产生 `/api/api/...`。
3. **CORS 解析**：`ALLOWED_ORIGINS` 按逗号拆分、逐项 `strip()`、忽略空项。未配置时保留 localhost/127.0.0.1 的 Vite 5173/5174/5175 默认白名单。生产同域部署时浏览器请求与页面同源，通常不触发跨源 CORS；若有跨源前端，则应在 `.env` 显式配置生产 origin，此配置会替换默认本地白名单。
4. **存储兼容**：沿用当前工作区已有 `StorageConfig`：`DATA_DIR/tutor_agent.db` 与 `DATA_DIR/chroma_db`；本工作包未重新设计数据库、Chroma 或 repository。
5. **测试隔离**：journal API 测试 monkeypatch repository 列表函数返回空列表，不调用真实 LLM、Embedding、Reranker 或外部网络。

## 6. 失败尝试

1. 基线目标测试文件不存在，pytest 返回路径不存在错误；这是测试文件尚未创建的环境/基线状态，不是业务测试失败。

## 7. 已知风险

- nginx 配置不在本工作包允许修改范围内，因此无法在本地验证实际 `proxy_pass`/rewrite 行为；部署时必须确保 `/api` 只由 nginx 去除一次。
- `ROOT_PATH` 在模块导入时读取环境变量；运行进程变更环境后需要重启，符合服务配置的通常行为。
- `ALLOWED_ORIGINS` 已配置但为空时结果为空列表；这表示不允许跨源 origin，适合生产同域部署，但跨源前端必须显式配置 origin。
- 当前 pytest 仍有 Chroma 依赖产生的既有 `DeprecationWarning`，不影响退出码和测试结果。
