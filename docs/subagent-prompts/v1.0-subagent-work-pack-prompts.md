# Totur-Agent v1.0 子代理工作包提示词

> 版本：v1.0  
> 创建日期：2026-07-28  
> 适用仓库：`E:\AI Project\Totur-Agent`  
> 目的：将 v1.0 后续开发拆成三个独立工作包，由项目负责人逐个指定给子代理执行。

## 0. 人工调度顺序

必须按以下顺序执行，不要同时指定多个代理修改同一工作区：

1. **代理 A：API/代理契约修正**
2. **代理 B：SSE、日记、备份自动化测试补齐**
3. **代理 C：Docker、Compose、nginx 和本地生产验证制品**
4. 主代理或项目负责人统一运行全量测试、审查 diff、决定是否提交 Git

> 代理 B 可以在代理 A 完成后开始。代理 C 必须在 A 的 `/api` 契约和 `/data` 路径契约稳定后开始。

将下面内容复制到每个子代理任务的开头：


## 2. 代理 A 提示词：API/代理契约修正

### 2.1 任务提示词

```text
你是工作包 A 代理，负责 Totur-Agent v1.0 的 API/反向代理契约修正。

先阅读：
- AGENTS.md
- docs/requirements.md
- docs/api-design.md
- docs/data-design.md
- docs/1.0 开发文档 .md（仅作历史参考）
- app/config.py
- app/main.py
- app/api/routes/journal.py
- frontend/src/api/tutorApi.js

写入范围严格限制为：
- app/config.py
- app/main.py
- app/api/routes/journal.py
- tests/test_server_config.py（允许新建）
- tests/test_journal_api.py（允许新建）
- docs/subagent-reports/v1.0-A-api-proxy-contract-report.md（必须新建）

禁止修改：
- frontend/ 下任何文件
- Dockerfile、Compose、nginx 文件
- Agent 核心逻辑、RAG 逻辑、数据库 repository（除非任务范围内的测试无法隔离）
- 其他代理的报告

目标：
1. 固定生产 API 契约：前端使用 `/api` 作为 API 基址；nginx 负责去掉 `/api` 后转发到现有 FastAPI 无前缀路由。
2. `app/api/routes/journal.py` 不得再使用 `/api/journal` 作为 FastAPI 路由前缀，避免代理去前缀后出现 `/api/api/journal`；应与现有路由风格保持一致。
3. `ROOT_PATH` 只用于 FastAPI 的代理上下文、OpenAPI 或 URL 生成，不得把它误当成真实路由前缀；不要同时在 nginx 和 FastAPI 做两次 `/api` 前缀。
4. `ALLOWED_ORIGINS` 从环境变量读取：支持逗号分隔、去除空白、忽略空项；未配置时保留本地开发默认白名单。明确生产同域部署时的行为。
5. 检查 `DATA_DIR` 与 SQLite/Chroma 的配置读取是否保持兼容，不要在本工作包重新设计存储层。
6. 为以上行为补充最小、稳定、可重复的测试；测试不得调用真实 LLM、Embedding、Reranker 或外部网络。

建议验收点：
- app 的 journal 路由表中出现 `/journal` 或 `/journal/entries`，而不是 `/api/journal`。
- 设置 `ROOT_PATH=/api` 不会让 FastAPI 路由实际变成 `/api/api/...`。
- `ALLOWED_ORIGINS="https://example.com, http://localhost:5173,,"` 解析结果正确。
- 未设置 `ALLOWED_ORIGINS` 时，本地 Vite 默认 origin 仍可用。
- journal API 的最小路由测试通过。
- 原有相关测试不回归。

执行步骤：
1. 先运行相关现状测试，记录基线。
2. 先添加/调整失败测试，确认失败原因是缺少目标行为。
3. 实现最小改动。
4. 运行：
   - `.\\.venv\\Scripts\\python.exe -m pytest tests/test_server_config.py tests/test_journal_api.py -q`（文件存在时）
   - `.\\.venv\\Scripts\\python.exe -m pytest tests/test_main_lifespan.py tests/test_stage2_api.py -q`
5. 检查 `git diff --check`、`git diff --stat` 和 `git status --short`。
6. 写报告：`docs/subagent-reports/v1.0-A-api-proxy-contract-report.md`。

交付物：
- 允许范围内的代码和测试修改
- 上述版本化 Markdown 报告
- 最终回复中的测试结果和风险清单
- 不提交 git commit
```

### 2.2 代理 A 报告最低要求

报告至少包含：

- `ROOT_PATH` 和 nginx strip-prefix 的责任边界

- 修改文件与测试文件
